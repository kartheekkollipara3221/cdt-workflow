# Phase 4 Gap Closure Plan: Implement Inspection Commands

## Gap

UAT test 4 found that `show`, `show-tasks`, `show-history`, and `show-notifications` are accepted command names but return the placeholder "recognized but not implemented yet" response.

## Root Cause

`CommandRegistry.RequiredCommandNames` lists the commands, but `Dispatch` only has real branches for `init-db`, `verify-seed`, `start-workflow`, `execute-json`, and `show-context`. The missing commands have no application handlers, no DI registration, and no read-model services.

## Fix Tasks

1. Add read-only inspection services over EF Core for:
   - workflow instance summary by `WorkflowInstanceId`
   - workflow tasks by `WorkflowInstanceId`
   - workflow audit history by `WorkflowInstanceId`
   - notification outbox rows by `WorkflowInstanceId`

2. Add command handlers:
   - `show <workflowInstanceId>`
   - `show-tasks <workflowInstanceId>`
   - `show-history <workflowInstanceId>`
   - `show-notifications <workflowInstanceId>`

3. Register handlers and services in `Program.cs` / infrastructure DI.

4. Update `CommandRegistry.Dispatch` to route each command to its handler instead of falling through to the placeholder response.

5. Add focused tests that prove:
   - each command returns useful output for an existing workflow instance
   - missing instances return a non-zero failure result
   - `CommandRegistryTests` no longer allow placeholder output for these commands
   - branch UAT visibility is possible: closed task, pending Maker rework task, returned notification, and audit action are visible

## Guardrails

- Keep these commands read-only.
- Do not add new schema or third-party packages.
- Do not hardcode Portfolio Trade behavior into the engine; Portfolio Trade keys may appear only in tests/sample assertions.
- Use existing EF Core entities and existing output style.
- Use `TimeProvider` only if command output needs current-time computation; otherwise do not introduce timestamps.

# C13: bounded outbox and durable retries

User approved the proposal on 2026-10-14. Execute inline using GSD quick tracking; milestones remain unchanged.

1. Add SQL-backed regression cases proving configurable batches and deferred retries (red first).
2. Add validated optional Notifications:Outbox configuration, preserving the existing three-argument constructors and legacy defaults. Limit backlog candidate and warning materialization; project lightweight candidate metadata, load bodies only after claim. Persist NextAttemptAtUtc on failed release using TimeProvider; honor it in both delivery paths and atomic claims. Unlimited attempts; no dead-letter policy.
3. Add EF migration/snapshot and idempotent standalone SQL upgrade with no runtime-data rewrite. Null timing means immediately eligible. Add an eligibility index.
4. Test retry boundaries/cap/recovery, invalid rows, batching/order, concurrency, lease recovery, API cooperation, configuration and in-place upgrade. Run core/API suites sequentially, warning-as-error builds, seed/sample regression and local SMTP coverage if available.
5. Document rollout: no workflow closure; drain/pause all notification consumers, schema first, deploy consumers, then opt in (100 rows, 60-second initial retry, 3600-second cap). Keep additive schema on rollback. SMTP is at least once.
6. Record evidence and remaining limitations in SUMMARY, STATE and handoff. Commit only task files; preserve unrelated reports. No production deployment.

Compatibility: batch PendingCount describes selected candidates, as before; API synchronous action delivery remains scoped to that action and is not truncated by the backlog batch setting. Existing deployments without settings keep unlimited batch/immediate retries; persisted future retry dates are always honored by new consumers.

Workflow API JSON Bodies and Console Usage

Current contract for UI integration. The HTTP DTO and the console test envelope are intentionally different.

The public API accepts application-owned workflow input only. It derives current state, task, version, business-object type, transition destination, final To/Cc placement, SLA timing, correlation, and idempotency identity.

Trusted actor headers

X-Workflow-UserId: maker1
X-Workflow-Roles: Maker
X-Workflow-DisplayName: Maker One

The browser body does not own actor identity. The reference host uses trusted headers as a temporary adapter.

POST /v1/WorkflowStart

{
  "workflowKey": "PortfolioTrade",
  "businessObjectId": "PT-1001",
  "actionKey": "SubmitForChecker",
  "notification": {
    "recipientInputs": {
      "originalMaker": [
        {
          "userId": "maker1",
          "emailAddress": "maker@example.test",
          "displayName": "Maker One"
        }
      ],
      "selectedCcUsers": []
    },
    "templateData": {
      "referenceNumber": "1050",
      "submitterDisplayName": "Maker One",
      "tradeLink": "https://example.test/trades/PT-1001"
    }
  }
}

workflowKey and businessObjectId are required. actionKey, slaTargetDate, and notification are optional structurally and are required only when the selected metadata path needs them. The seeded workflow declares one required immutable originalMaker participant, so the UI resolves and sends it on Start. The engine captures it once.

SLA-only synchronization through the same endpoint

{
  "workflowInstanceId": "WF-PT-1001",
  "slaTargetDate": "2030-01-25"
}

An action key may be omitted only when slaTargetDate is present.

Recipient ownership

ValueOwnerBehavior
Original Maker identity/addressUI resolves; Start capturesImmutable for the workflow lifetime.
Selected copied usersUI resolves on allowed routesAccepted only under metadata-declared input keys.
Static addressesVersioned workflow metadataNot sent by the UI.
Final To/Cc arraysWorkflow engineResolved from ordered rules and stored on the created task.
SLA reminder recipientsTask snapshotCopied unchanged; metadata is not re-resolved.

Address strings are opaque stored values. Capture and resolution perform no syntax, directory, mailbox, or SMTP validation and do not trim or rewrite them. The resolver compares duplicates case-insensitively, retains the first opaque value, and removes a Cc value when the same address is already in To.

Fields rejected from the public body

Unknown root and nested properties fail JSON binding. This includes the legacy public fields businessObjectType, initialActionKey, idempotencyKey, slaInput, notificationContext, and notificationRecipients, plus UI echo, form payload, toState, current-state guards, request metadata, and SLA configuration.

Console-only WorkflowActionEnvelope

Files under samples/workflow-actions are internal engine fixtures for execute-json. Their large WorkflowActionEnvelope, form-data test payload, explicit IDs, guards, and final recipient arrays must not be copied into the UI HTTP contract. 
dotnet run --project src/WorkflowEngine.Console -- init-db
dotnet run --project src/WorkflowEngine.Console -- verify-seed
dotnet run --project src/WorkflowEngine.Console -- start-workflow PortfolioTrade PT-1001 --user maker1 --reset
dotnet run --project src/WorkflowEngine.Console -- execute-json samples/workflow-actions/02-submit-for-checker.json
dotnet run --project src/WorkflowEngine.Console -- run-sla --now "2030-01-20T14:00:00Z"

Canonical public examples are in workflow-api/samples. Full rules are in workflow-api/WORKFLOW_API_BOUNDARIES.md.

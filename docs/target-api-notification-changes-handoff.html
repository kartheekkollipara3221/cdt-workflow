Target API Handoff: Metadata-Resolved Notifications

Integration outcome

The target application supplies only resolved participant/request inputs and template data. Versioned workflow metadata declares which sources a route uses and whether each source contributes To or Cc. The engine persists one final task/outbox recipient snapshot and reuses it for SLA reminders.

Public DTOs

public sealed class WorkflowNotificationRequest
{
    public Dictionary<string, List<WorkflowRecipientRequest>?>? RecipientInputs { get; set; }
    public Dictionary<string, string?>? TemplateData { get; set; }
}

public sealed class WorkflowRecipientRequest
{
    public string? UserId { get; set; }
    public string? EmailAddress { get; set; }
    public string? DisplayName { get; set; }
}

Start has exactly workflowKey, businessObjectId, actionKey, slaTargetDate, and notification. Action has exactly workflowInstanceId, actionKey, assignedRoleKey, slaTargetDate, and notification.

Target application responsibilities

ResponsibilityRequired behavior
ActorMap authenticated user ID, display name, and roles into the trusted workflow actor boundary.
Original MakerResolve it before Start and send exactly one value under originalMaker.
UI-selected copied usersSend ordered values under selectedCcUsers only for routes whose metadata declares that key.
Template dataSend plain string values under notification.templateData. Do not send HTML.
Business dateMap the application field to flat slaTargetDate; do not send SLA schedule configuration.
Form persistenceSave business/form data in the target API before calling workflow.

Workflow engine responsibilities

  • Derive businessObjectType from the active workflow definition.
  • Capture immutable workflow participants transactionally with Start.
  • Reject undeclared recipient input keys before task, notification, audit, or idempotency side effects.
  • Resolve StaticAddress, WorkflowParticipant, and RequestInput sources in metadata rule order.
  • Deduplicate addresses case-insensitively, retain the first opaque string, and give To precedence over Cc.
  • Store the resolved JSON on the task and immediate outbox row.
  • Copy the task snapshot unchanged for every SLA due/overdue row.
  • Maintain one message-level outbox status and retry count.
Address strings are storage values, not verified mailboxes. Participant capture and recipient resolution do not validate syntax, directory membership, mailbox existence, or SMTP reachability and do not trim or rewrite the supplied address. A sender-level parse/send failure returns the whole outbox row to Pending and increments its one retry count.

Metadata and runtime tables

TablePurpose
WorkflowDefinitionOwns the generic business-object type.
WorkflowParticipantDefinitionDeclares participant keys, cardinality, requiredness, and immutability.
WorkflowParticipantStores workflow-lifetime participant snapshots such as Original Maker.
NotificationRecipientRuleMaps ordered source rules to To/Cc for each notification route.
WorkflowTaskStores the final recipient and template-context snapshots used throughout the task lifetime.

Composition and dispatch

  • Register the shared workflow infrastructure, TimeProvider, API services, notification dispatcher, and configured sender.
  • Execute workflow through the shared application/infrastructure services; do not duplicate transition or recipient resolution logic in controllers.
  • After commit, dispatch only action-created rows selected by workflow instance ID and correlation ID.
  • Keep Smtp:RecipientOverride enabled during controlled live smoke tests.
  • Run SLA and generic outbox processing from a scheduler/worker, not a polling loop inside the request host.

Verification checklist

  • Start without required Original Maker fails and rolls back the new instance.
  • A later action cannot replace immutable Original Maker.
  • An undeclared request input key fails before side effects.
  • Static To plus selected Cc resolves in deterministic order.
  • Duplicate case variants retain the first string and To removes the same address from Cc.
  • Immediate outbox JSON equals task JSON.
  • SLA JSON remains byte-for-byte equal after metadata/participant changes.
  • An unusable stored address produces one message-level delivery failure/retry.

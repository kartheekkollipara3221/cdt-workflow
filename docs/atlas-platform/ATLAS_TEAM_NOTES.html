Atlas platform: what the code does not tell you

You can read the code. This page gives the things that the code does not show: the reasons for some designs, the things that must stay the same, the known limits, and how to report a platform bug.

1. Decisions and reasons

Each item below can look like extra code or a strange choice. Do not "simplify" it. The reason is given.

DesignReasonIf you remove it
The current if chains stay in CPAtlasService. The PLATFORM line runs first.The current apps must not change. The platform is additive.The current apps stop.
AtlasAppCode.ToLegacy(...) in place of Enum.Parse<CPApplicationCode>It gives the same enum for the current codes. For a disabled platform app, it gives 404, not a logged 500.A switched-off TTDV2 gives 500 errors.
The server runs the rules, effects, validators and computed values again at save.The client is only for user feedback. A user can change the browser request.A user can save read-only fields or values that are not permitted.
ClearRuleHiddenValues at loadA field that a rule hides must not be in the response JSON. Hidden on the screen is not enough.Hidden data goes to the browser.
RuleMode: MostPermissive for TTDV2A Prepare user matches the @Read rule (read-only) and the owner rule (editable). With FirstMatch, only the first rule counts.Prepare users cannot edit their own records.
KeepSavedValue on the drop-downsThe lists change with time (years, week endings, users, accounts). An old record must still show its saved value.Old records show empty fields, and a save can lose the value.
The dashboard query takes names only from the table registry. Each value is a SQL parameter.The JSON is data. It must not be able to inject SQL.SQL injection risk.
IsDeleted is bit NOT NULL DEFAULT 0, and the filtered indexes use WHERE [IsDeleted] = 0.The query uses = 0, so SQL Server can use the filtered indexes.The "Current Tax Timesheet" tab becomes slow.
Free-text columns are nvarchar.Names and descriptions can have non-Latin characters.Characters are lost.
Audit is on the server (AuditMode: Server) and in the same transaction as the data.The history must be complete and correct. A client audit call can be lost or changed.The history can have gaps.
No audit row when nothing changedThe History Log shows only real changes.The history fills with empty updates.
LogMessage is JSON text in the target formatThe target History Log does JSON.parse(LogMessage).The History Log breaks for TTDV2.
Config files and table metadata are read one time at start-up.Simple and fast. No file watchers, no cache timing.—
OnStartupError: DisableModule (default)A config error in one platform app must not stop the current apps.One bad JSON file stops the whole host.
The start-up also runs as a hosted service.If program.cs does not call StartAtlasPlatformAsync, the tables still load before the first request.The first requests fail.
The settings come only from the configuration given to AddAtlasPlatform(configuration).The target program.cs builds its own root from appsettings.json. The platform uses the same source.Settings in other places are not read.
The Tailwind safelistTailwind reads only src/**/*.{html,ts}. The classes in the server JSON are not found.The form layout is one long column.
Shared case files (atlas-validator-cases.ts, atlas-effect-cases.ts)The client tests and the server tests read the same cases, so the two sides stay the same.The client and the server can give different results.

2. Things that must stay the same

  • Platform files: the source repo (atlas-platform/) owns them. Do not edit them at the target. A local fix is lost at the next package copy.
  • Stable identifiers: do not rename app codes, role names (Read, Prepare, Owner), table names, column names, JSON keys, control names or log event IDs (41001 to 41024). Other parts and saved data use them.
  • Database changes: SQL scripts only, additive, and safe to run again. Do not use EF migrations for platform tables. Do not alter or drop the current tables.
  • Scaffold: if you scaffold CPSharepointContext from the database again, leave out the TTDV2 tables, CP_Atlas_ScriptLog and the view. AtlasPlatformContext maps them.
  • Public contracts: changes to the v1/... requests and responses must be additive. New fields must be optional.
  • Platform DTO properties: they are in Data/Platform/Dto/CPPlatformDto.cs and are optional. Null means the current behavior.
  • Platform app code: a new app must not need new C# or TypeScript. If it does, ask first. The need can be a missing generic feature.

3. Known limits

LimitWhat to do
A change to a config file or an app table is not seen until a restart.Restart the app pool. Then run --atlas-check.
The platform I/O is synchronous, as the target code is (review AR-04, PF1).Measure in dev with real data. A decision on async I/O comes after the measurements.
The start-up check opens a second SQL connection (RV-L14).It works. It changes with the next change in that method.
After a short SQL failure at start-up, a disabled app does not come back by itself (RV-07, part).Restart the app pool when SQL is available again.
The platform dashboard runs only Source: "Table" tabs. It does not run Procedure tabs (RV-N1).Use Table tabs. Fix this before an app needs a procedure tab.
A user control value (a LAN ID) is not validated (RV-L03).TTDV2 has only a disabled user control. Decide the rule before an app has an editable one.
090 gives back only the TTD roles that 050 revoked in the hour before the 050 log row.Run 090 only for a rollback, soon after 050.
CPAtlasDashboard.Code is the enum, not nullable. For TTDV2 it is 0 (= CDT).A client must use AppCode when it is there.
No attachments in P1TTDV2 has no attachment table.
CAUTION: Do not run 050 in the shared dev database. It soft-revokes the TTD roles of all users. It runs only on the change-over day. Run 090 only for a rollback.

5. Behavior that testers can think is a bug

BehaviorWhy it is correct
After a save, the form goes back to the dashboard.This is the same as the current section master.
WeekEnding shows the last Sunday and the next 3 Sundays. The default is the last Sunday (today, if today is Sunday).WeekEndings provider, Count: 4.
TaxYear shows next year down to 3 years ago. The default is this year.Years provider (Before: 3, After: 1). The list starts with the latest year, so {Options[1]} is this year.
Dashboard dates show as dd-MMM-yyyy, for example 18-Oct-2026.The platform date format.
A Prepare user sees another user's record as read-only, with no Save button.Edit.Own: [Prepare] and the owner rule.
A save with no change writes no History entry.By design (section 1).
Minutes like 1.5, 1:30, -5 or 1441 are refused.Whole minutes from 0 to 1440 only.
AccountNumber and AccountName cannot be typed.They come from the selected Account.
A deleted record is not in any tab.Soft delete: IsDeleted = 1. The row stays in the table.
In LogOnly mode, a user without access can still do the action.The denial is only logged (Atlas.AccessDenied). Enforce gives 403.

6. How to report a platform bug

6.1 What to send

  1. App and screen: for example TTDV2, form, record 10005.
  2. User role: Read, Prepare or Owner, and if the user owns the record.
  3. Action: what the user did.
  4. Result: the message on the screen, the browser console error, and the failed network call (URL, status, response body).
  5. Server log: the lines with Atlas. and the event ID (for example Atlas.FieldRefused 41013).
  6. Expected: what you expected.
  7. Current apps: do they still operate? If not, this is the highest priority.

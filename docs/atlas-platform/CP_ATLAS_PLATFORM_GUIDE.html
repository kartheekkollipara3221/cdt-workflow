2. What the platform is

CP Atlas is one product with two components in this repo: the workflow engine and the Atlas platform. This guide is about the platform (atlas-platform/).

The goal

Each current Atlas app has its own C# service, its own entity classes and its own screen code. The platform replaces this with one generic server service and one generic form. A new app is data:

  • One SQL script (schema, tables, app row, roles).
  • Three JSON files: the manifest <CODE>.app.json, the form <CODE>.json, the dashboard <CODE>.Dashboard.json.
  • One registration line in program.cs: AddAtlasModule<ConfigSectionService>("<CODE>").

A new app needs no new C# and no new TypeScript. TTDV2 is the pilot app. It is metadata, not a special case in the code.

What stays target code

The target team owns the target code: program.cs, CPAtlasService, the controllers, cp-atlas-dashboard.ts, the app component, the routes and the current services. The platform does not add controllers or endpoints. It uses the current v1/... routes. The integration adds a small number of lines to the target files (section 9).

The current apps do not change

The current apps are TTD, CDT, SQMSO, SQMSB and AIN. Each platform line in a shared target file runs first. For a current app it does nothing, and the current if chain runs as before. This is the fall-through rule.

4. Start-up, check and logs

4.1 Registration

Two extension methods in AtlasPlatformServiceCollectionExtensions.cs register the platform:

builder.Services.AddAtlasPlatform(configuration);                 // all platform services
builder.Services.AddAtlasModule<ConfigSectionService>("TTDV2");   // one line for each app
var app = builder.Build();
await app.Services.StartAtlasPlatformAsync();                      // optional: a hosted service does the same
  • AddAtlasPlatform(configuration) registers the config store, the resolver, the data services (AddAtlasPlatformData), the current user source, the error filter AtlasProblemExceptionFilter, the services of AtlasPlatformServices.Add and the hosted service AtlasPlatformStartupService. It reads the platform settings only from the configuration parameter. A TimeProvider that the host registers has priority (TryAddSingleton).
  • AddAtlasModule<TService>(appCode) registers one app. The code must match ^[A-Z][A-Z0-9]{1,19}$. A second line for the same code throws "The app code 'X' is registered twice".
  • StartAtlasPlatformAsync loads the table metadata and runs the start-up check. A second call does nothing (AtlasTableRegistry.IsLoaded, one start-up at a time with AtlasPlatformStartupGate).

4.2 What the start-up does

  1. AtlasConfigStore reads each *.app.json in the config folder, then the form and dashboard files that the manifests name. It applies the settings AppSettings:Modules:<CODE>:* to each manifest.
  2. The start-up collects Table, AuditTable and AttachmentTable of each registered manifest (also disabled ones).
  3. AtlasColumnMetadataReader.LoadAsync reads the columns from sys.tables, sys.schemas and sys.columns. AtlasTableRegistry keeps them in memory.
  4. AtlasStartupCheck.Run compares the manifests and JSON files with the tables, the registration lines and the option providers. AtlasConfigLint adds the JSON checks.
  5. Each item is logged (Atlas.StartupCheck, 41020). An error disables the app (AtlasDisabledApps, log Atlas.AppDisabled 41023 at Critical), or stops the host when OnStartupError is Stop.

4.3 Start-up error mode

AppSettings:Atlas:OnStartupErrorResult of a start-up error
DisableModule (default, also when no value)The host starts. The current apps operate. Each platform app with an error is not available: 404, not in the menu. An error for all apps (*, for example SQL is not available) disables all platform apps.
StopThe start-up throws InvalidOperationException and the host does not start. Use it only when you set it on purpose.
A value that is not validDisableModule, and an error for all platform apps (--atlas-check returns 1).

4.4 When is an app available

IAtlasModuleResolver.IsPlatformApp(code) is true only when all of these conditions are true:

  • The code has an AddAtlasModule line.
  • The manifest has Enabled: true (after the settings).
  • The Table (and the AuditTable when AuditMode is Server) loaded at start-up.
  • The start-up check did not disable the app.

Each PLATFORM line in CPAtlasService uses this test. When it is false for a code, the current if chain runs.

4.5 Config is read one time

The config store reads the manifests, forms and dashboards one time, at the first use (the platform start-up). The table metadata is also read one time. After a change to a config file or to an app table, restart the app pool. This is the design, not a defect. AppSettings:ConfigRefreshSeconds is not read.

Each call of GetForm or GetDashboard gives a new copy of the object, so a request can change its copy. A manifest file that cannot be read removes only its own app (log Atlas.ConfigInvalid, 41021).

4.6 The --atlas-check command

RunAtlasCheckAsync runs the same load and check with no web server, and prints a report:

dotnet run --project atlas-platform/src/BBH.CP.Atlas.App --launch-profile StandIn -- --atlas-check
BBH.CP.Atlas.App.exe --atlas-check --environment QC                  (at the target)

  Settings from: ...

The exit code is 0 when there are no errors and 1 when there are errors. The line Settings from: names the configuration sources. Run the check before each release and after each config change.

4.7 What the check finds

  • Errors: the manifest code and registration line (both directions), the app row and Parent, the tables and their key (ID must be int IDENTITY), unsupported column types, form fields, OwnerFields, SoftDelete (must be IsDeleted, type bit), Computed, Defaults, option providers, dashboard tabs (names, operators, values, MaxRows greater than 0), a form with no Permissions block, setting values that are not valid.
  • Errors from AtlasConfigLint.CheckForm: duplicate control names, effect and rule targets that are not a control, unknown default tokens, a Pattern that does not compile, an unknown button Action.Type, a SchemaVersion higher than 1.
  • Warnings: a disabled manifest, an unknown role in rules or Permissions, JSON properties that are not DTO properties (AtlasConfigLint.CheckUnknownProperties, with the JSON path), a control type that the client does not render, AccessMode LogOnly outside Development, a shared AuditTable with no AuditRefTypes.

The current apps have no manifests, so the check does not check them. The TTDV2 files give 0 errors and 0 warnings.

5. The TTDV2 flow, end to end

This section follows one TTDV2 timesheet record through each step. The examples come from TTDV2.app.json, TTDV2.json and TTDV2.Dashboard.json. The main table is TTDV2.General. The audit table is TTDV2.AuditLog.

The main rule. The client is for the user. The server is the authority. Rules, validators, effects and computed values run on the client for fast feedback, and the server does each check again at save. The shared case files (atlas-validator-cases.ts, atlas-effect-cases.ts) are tested on both sides.

5.1 Roles and test users

040-ttdv2-app.sql makes three TTDV2 roles in dbo.CP_Atlas_Entitlement. The role flags give the tokens @Read, @Write and @Admin (AtlasAppRoles). Admin includes write and read; write includes read.

5.2 Menu: GET v1/Application

  1. The target app component calls v1/Application. The platform form calls the same endpoint through AtlasApiService.applications.
  2. CPAtlasController.GetApplication calls CPAtlasService.GetApplication. It runs the current procedure dbo.Get_Application for the LAN ID.
  3. PLATFORM line, after the procedure call: AtlasApplicationMenu.Enrich(result, resolver, configStore, logger).
  4. Enrich adds FormType (TTDV2: FORM) and HasDashboard (true when the manifest has a Dashboard) to each available platform row. It keeps the current app rows and the rows with no code with no change. It removes rows of codes that are not a current app and not an available platform app.
  5. When Enrich throws, it returns the procedure rows with no change and logs Atlas.ConfigError. Thus the menu of the current apps cannot fail because of the platform.
  6. The target menu shows an app only when HasDashboard is not false (integration edit).

5.3 Dashboard: GET v1/Dashboard?code=TTDV2

  1. The target cp-atlas-dashboard.ts calls loadDashboard(code).
  2. CPAtlasController.LoadDashboard(string code) calls CPAtlasService.LoadDashboard(string code).

  • Add New: onClick(controlName) calls atlasNavigation.open(null, 0, button.Target). The button Target is { "AppCode": "TTDV2", "Id": 0 }. The route is /form/TTDV2/0.

8. Security and access

Authentication is target code (IIS Windows authentication, IUserInfo). UserInfoCurrentUserSource gives the current user to the platform. AtlasUserContext reads the roles of the user one time for each request from dbo.vw_CP_Atlas_ActiveUserRole (the app and its parent).

8.1 Three mechanisms

MechanismInputOutputRuns on
PermissionsRoles, flags, ownerAllow or refuse an operation (View, Create, Edit, Delete, History)Server (AtlasAccessService)
RulesRoles, flags, owner, statesVisible, hidden, read-only or editable partsServer (AtlasRuleEngine)
EffectsField valuesShow, hide, require, set, clear other fieldsClient and server

8.2 Access decisions

  • A user with no role in the app is refused for each operation.
  • View: the View list (no list = allowed). History: the History list, else the View result. Create and Delete: their lists.
  • Edit: Edit.All allows all records; Edit.Own allows only records where the user LAN ID is in one of the OwnerFields (case of the column name does not matter).
  • A list entry matches a role name or a flag token (@Read, @Write, @Admin). An empty list matches nobody.
  • UserPermissions tells the client CanCreate, CanEdit, CanDelete, CanViewHistory. In LogOnly, CanEdit is always true, so the Save button stays; the rules still make the fields read-only.

8.3 AccessMode

ModeResult of a refused operation
LogOnlyLogs Atlas.AccessDenied (41001) and continues for View, Edit and History, and for the load of a new form. A refused Delete and a refused save of a new record give 403. Use it while the role grants are checked.
EnforceLogs Atlas.AccessDenied and gives 403 "Access denied".
Module offEnabled = false (or disabled by the check): 404, not in the menu. The current apps operate. This is the rollback switch, not an access mode.

A setting value that is not valid fails closed: Enabled becomes false, AccessMode becomes Enforce, and the start-up check gives an error. The check warns when AccessMode is LogOnly outside Development.

8.4 Rules for TTDV2

RuleMode: MostPermissive: all matched rules count. A part is visible when one rule makes it visible, and disabled only when all matched rules disable it. RuleDefault: ReadOnly: when no rule matches, a part is visible but disabled.

UserMatched rulesForm
Read@ReadRead-only

With FirstMatch, a Prepare user would match only the first rule and could never edit. A child control that the JSON disables stays disabled unless a rule names it in EnableControls. An effect cannot show a field that a rule hid. CPRule.States is not used yet: the rule context gets an empty state list (no workflow in P1).

8.5 Record visibility and hidden data

  • The dashboard filters decide which rows a user sees in a tab (for example {LanId} filters). A hidden tab gets no rows.
  • Each Edit, Delete and History request checks the access again for the record on the server.
  • At load, a rule-hidden field gets no value and no options. At save, a value for a hidden or disabled field is refused. The save response has no rule-hidden fields.
  • In History, a rule-hidden field shows *** (AtlasAuditMask). A control with Audit: false is stored as ***.

8.6 What gives 403

  • Enforce: any refused View, Create, Edit, Delete or History (dashboard, load, save, delete, history).
  • All modes: a refused Delete; a refused save of a new record.

The problem body is ProblemDetails with title "Access denied" and the reason in detail.

Restart the app pool after a change to: a setting, a manifest, a form or dashboard file, an app table (a new column or a new type), or a role structure that the start-up check uses. After the restart, run --atlas-check. After a short SQL failure at start-up, a disabled app does not come back by itself: restart when SQL is available.

12. How to change the platform safely

12.1 Backward compatibility

  • The current apps (TTD, CDT, SQMSO, SQMSB, AIN) must not change. A platform line in a shared target file runs first and falls through.
  • Changes to the v1/... requests and responses are additive. New fields are optional.
  • Stable identifiers: app codes, role names, table and column names, JSON keys, control names, log event IDs 41001 to 41024. Do not rename them.
  • Database changes: SQL scripts only, additive, idempotent, with a CP_Atlas_ScriptLog row. No EF migrations, no EnsureCreated, no automatic seeding for platform tables.
  • No new package. Use only what the target has.
  • Keep public .NET surfaces: add overloads or optional parameters (for example FindActive(..., tracking), ToWire(..., utc)), do not change a signature.
  • Use TimeProvider. Do not call DateTime.UtcNow outside the composition root.

12.2 Keep it generic

A new app must not need new C# or TypeScript. Do not put field-name if chains, fixed field lists or app redirects in the platform. If an app needs something, add a generic feature (a token, an option provider, an effect, a control type) that the JSON turns on. To add a computed function, change AtlasComputedFields; to add a token, change AtlasDefaultTokens; to add a control type, call provideAtlasRenderers or AtlasRendererRegistry.register.

12.3 Stop and ask first

  • A change to a persisted column, a stable identifier, or a v1/... contract.
  • A new package, or a new target file that must change.
  • A fix that needs app-specific code in the platform.
  • Any change to 050 or 090, including R01 and R02.
  • The PROJECT.md section 22 triggers that apply (for example DateTime.UtcNow, engine adapter work).

12.4 The change path

  1. Change the file in the platform source.
  2. Add or change a test.
  3. Run the 5 gates.
  4. Commit. Rebuild the bundle if a copied file changed.
  5. Copy the changed files to the target. Do the hand edits only if INTEGRATION.md section 2 changed.
  6. Test TTDV2 and one current app at the target.

14. Glossary

Platform
The generic, metadata-driven app layer of CP Atlas in atlas-platform/.
Platform app
An app that the platform serves: a manifest, a registration line, enabled, tables loaded. TTDV2 is the pilot.
Current app
An app with its own code at the target: TTD, CDT, SQMSO, SQMSB, AIN. Its code is in the enum CPApplicationCode.
Target
The CP Atlas code of the target team (back end and WebUi).
Manifest
The file <CODE>.app.json (AtlasAppManifest).
Form file, dashboard file
<CODE>.json and <CODE>.Dashboard.json.
Registration line
One AddAtlasModule<ConfigSectionService>("<CODE>") line in program.cs.
PLATFORM line
A line in a shared target method that sends a platform app to the platform and does nothing for a current app.
Fall-through rule
The platform line runs first; for a current app, the current if chain runs after it with no change.
Stand-in
A local copy of target code (StandIn/, stand-in/) so that the platform builds and runs here. Not copied.
Bundle
The self-extracting file atlas-target-package.ps1 with copy/, reference/ and MANIFEST.txt.
Start-up check
AtlasStartupCheck.Run and AtlasConfigLint: compares the config with the tables and registrations. --atlas-check runs it with no web server.
Access mode
LogOnly (log a refusal and continue) or Enforce (403).
Rule
A CPRule: roles, owner and states give visible, hidden, read-only or editable parts.
Effect
A value-driven change of other fields (CPEffect), on the client and the server.
Permissions
The roles that allow each operation (CPPermissions).
Owner
A user whose LAN ID is in one of the OwnerFields of the record. Not the same as the role Owner.
Flag token
@Read, @Write, @Admin, from the role flags IsRead, IsWrite, IsAdmin.
Allow list
The save step that accepts only fields that the user can change (AtlasAllowList).
Server-set field
A system column, a Computed field or an effect target. The server ignores a sent value.
Soft delete
A delete that sets IsDeleted = 1. The row stays.
Version
The Base64 text of the rowversion column. The save compares it to find a conflict.
Wire value
The text form of a value in a request or response (AtlasValueConverter.ToWire, FromWire).
Change-over day
The day when 050 copies TTD to TTDV2 and TTD stops.
Gate
One of the 5 platform quality commands (section 11).

Executive Summary

Fact The CDT Workflow Engine is a completed console-style .NET 10 proof of concept. It uses SQL Server, EF Core, metadata-driven workflow transitions, idempotency, optimistic concurrency, SLA scanning, notification outbox records, audit history, and seed verification.

Fact The reusable engine is mainly in WorkflowEngine.Application, WorkflowEngine.Infrastructure, and WorkflowEngine.Domain. The console entry point and command handlers are adapters.

Important The target API project was not available. This migration was not implemented. This document package is an instruction package based on the real console repository and prior analysis. Only docs/api-conversion files were created or updated.

Recommended strategy: reference the reusable workflow projects from the external API solution, add controller-style endpoints, stamp actor identity from authenticated claims, and keep Portfolio Trade behavior in SQL metadata/seed data rather than controllers.

Current CDT Workflow Engine Architecture

Tests and samples tests/WorkflowEngine.Tests, samples/workflow-actions Behavior verification and sample envelopes. Keep as regression source; add API tests separately.

Why The Console Command Layer Should Not Become The API Layer

  • CommandRegistry dispatches CLI command names, not HTTP routes.
  • CommandArgumentParser parses command-line strings, not model-bound JSON/routes.
  • ExecuteJsonCommandHandler reads JSON files and supports CLI overrides.
  • StartWorkflowCommandHandler exposes demo reset behavior.
  • Show* handlers render console text.
  • DemoCommandHandler runs sample scripts and reset behavior.

The API should call IWorkflowExecutionService, IStartWorkflowService, IWorkflowContextReader, IWorkflowInspectionReader, IRunSlaService, and IProcessNotificationOutboxService directly.

Recommended Controller-Style API Architecture

API Component Purpose Key Rule
WorkflowInstancesController Start workflow instances. Use authenticated user; pass Reset=false for normal users.
WorkflowContextController Return form-open workflow context. Roles come from claims, not query/body.
WorkflowActionsController Execute one workflow action envelope. Stamp actor before validation, hashing, and execution.
WorkflowInspectionController Optional inspection of instance/tasks/history/notifications. Admin or support authorization only.
WorkflowAdminController Optional seed verification, SLA scan, outbox processing. Prefer deployment/hosted jobs; strict admin if exposed.

DI Registration Summary

  • Register TimeProvider.System.
  • Register WorkflowActionEnvelopeValidator, WorkflowActionEnvelopeNormalizer, CanonicalRequestHasher, WorkflowActionResultBuilder, and CanonicalWorkflowResultSerializer.
  • Call AddWorkflowInfrastructure(builder.Configuration).
  • Register API-specific IWorkflowActorResolver.
  • Register API-specific WorkflowHttpResultMapper.
  • Do not register console command handlers for normal API runtime.

Authenticated Actor Resolution Summary

The API must overwrite request body actor fields before validation, hashing, and execution. Workflow roles must come from authenticated claims, enterprise groups, or the existing API authorization system.

  • Do not add SQL user-role tables to the workflow schema.
  • Map claims to exact workflow role keys: Maker, Checker, TradingDesk, BDRMClientService.
  • Use the same actor resolver for context and execute endpoints.
  • Test that body roles are ignored or overwritten.

Database Migration And Seed Summary

  • Keep workflow migrations in WorkflowEngine.Infrastructure by default.
  • Apply migrations before enabling API endpoints.
  • Run Portfolio Trade seed data through WorkflowSeedService or WorkflowDatabaseInitializer.
  • Run SeedVerificationService after seed.
  • Do not run migrations or seed on every web request.
  • Do not expose public init-db endpoints.

SLA And Notification Outbox Summary

  • RunSlaService queues overdue notifications.
  • ProcessNotificationOutboxService claims and sends pending notifications.
  • Prefer hosted services or external scheduled jobs.
  • Use IServiceScopeFactory inside hosted services.
  • Use NoOpNotificationSender for tests and SmtpNotificationSender for production only with valid config.

Testing Strategy Summary

  • Keep existing library and console tests.
  • Add API controller tests for start, context, execute, admin gating, and route/body mismatch.
  • Add actor resolver tests for claim-to-workflow-role mapping.
  • Add HTTP result mapper tests.
  • Add SQL-backed integration tests; do not use EF Core InMemory for workflow persistence verification.
  • Use sample JSON as fixtures, but strip or ignore testExpectations.

Manual Migration Milestone Roadmap

  1. Prepare API project and references.
  2. Add workflow configuration.
  3. Register workflow services in Program.cs.
  4. Add authenticated actor resolver.
  5. Add start workflow controller.
  6. Add workflow context controller.
  7. Add execute workflow action controller.
  8. Add workflow result-to-HTTP mapper.
  9. Add admin/inspection endpoints if needed.
  10. Add SLA and notification outbox processing.
  11. Add migration/seed verification path.
  12. Add API tests.
  13. Run full verification.
  14. Cutover and cleanup.

Top Risks

  • Target API project was unavailable, so placeholders must be replaced manually.
  • Request body actor roles must not be trusted.
  • Reset and admin override must not be exposed publicly.
  • EF entities must not become public DTOs.
  • Migration ownership must be decided before database changes.
  • MockSectionData is POC storage unless deliberately accepted.
  • Hosted services must not inject scoped workflow services directly.
  • Raw dataSave.payload must not be logged by default.
  • Portfolio Trade transitions must not be hardcoded in controllers.

Final Checklist

  • Confirm API path, namespace, and controller conventions.
  • Reference Application, Infrastructure, and Domain.
  • Do not reference Console for API runtime.
  • Configure SQL Server connection string.
  • Configure notification sender per environment.
  • Register workflow services and actor resolver.
  • Stamp actor from authenticated claims.
  • Add start, context, and execute controllers.
  • Add result-to-HTTP mapper.
  • Decide admin endpoints and hosted jobs.
  • Apply migrations and seed data.
  • Run seed verification.
  • Add API tests for auth, status mapping, and sample flows.
  • Confirm no raw payload logging.
  • Confirm no public reset/admin override.
  • Run build, tests, HTTP smoke tests, and rollback rehearsal.

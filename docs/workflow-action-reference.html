Workflow action: evidence and SQL reference

Start with How one workflow action works. This page contains supporting checks, not a second walkthrough.

Read-only SQL

Run these queries against the disposable exercise database. Replace the instance ID with the value from the exercise. The table and column names come from WorkflowDbContext.OnModelCreating and its entities.

DECLARE @instance nvarchar(100) = N'WF-PT-ONBOARD-REPLACE';
DECLARE @definitionVersion bigint;
SELECT @definitionVersion = WorkflowDefinitionVersionId
FROM dbo.WorkflowInstance WHERE WorkflowInstanceId = @instance;

SELECT WorkflowInstanceId, BusinessObjectType, BusinessObjectId,
       WorkflowDefinitionVersionId, CurrentStateKey, Status, Version,
       StartedByUserId, StartedAtUtc, CompletedAtUtc
FROM dbo.WorkflowInstance WHERE WorkflowInstanceId = @instance;

SELECT FromStateKey, ActionKey, AllowedRoleKey, ToStateKey,
       TaskToCloseKey, TaskToCreateKey, NotificationRouteKey, IsActive
FROM dbo.WorkflowTransitionDefinition
WHERE WorkflowDefinitionVersionId = @definitionVersion
  AND FromStateKey = N'Draft' AND ActionKey = N'SubmitForChecker';

SELECT TaskKey, OwnerRoleKey, SlaPolicyKey, IsActive
FROM dbo.WorkflowTaskDefinition
WHERE WorkflowDefinitionVersionId = @definitionVersion
  AND TaskKey = N'CheckerReviewTask';

SELECT SlaPolicyKey, CalculationMode, DurationMinutes,
       RecurrenceIntervalMinutes, IsActive
FROM dbo.SlaPolicy
WHERE WorkflowDefinitionVersionId = @definitionVersion
  AND SlaPolicyKey = N'CheckerReviewSla';

SELECT Id, TaskKey, AssignedRoleKey, AssignedUserId, Status,
       CreatedAtUtc, DueAtUtc, NotificationRecipientsJson,
       NotificationRouteKey, NotificationContextJson
FROM dbo.WorkflowTask WHERE WorkflowInstanceId = @instance ORDER BY Id;

SELECT s.Id, s.WorkflowTaskId, s.ScheduleVersion, s.Status,
       s.SlaPolicyKey, s.CalculationMode, s.TargetDate,
       s.OverdueAtUtc, s.NextReminderAtUtc, s.RecurrenceIntervalMinutes
FROM dbo.WorkflowTaskSlaSchedule s
JOIN dbo.WorkflowTask t ON t.Id = s.WorkflowTaskId
WHERE t.WorkflowInstanceId = @instance ORDER BY s.Id;

SELECT o.Id, o.WorkflowTaskId, o.NotificationType, o.Status,
       o.Subject, o.NotificationRecipientsJson, o.CorrelationId,
       o.RetryCount, o.LastError, o.ProcessingStartedAtUtc, o.SentAtUtc
FROM dbo.NotificationOutbox o WHERE o.WorkflowInstanceId = @instance ORDER BY o.Id;

SELECT ActionKey, FromStateKey, ToStateKey, PerformedByUserId,
       PerformedByRoleKey, Reason, CorrelationId, CreatedAtUtc
FROM dbo.WorkflowAudit WHERE WorkflowInstanceId = @instance ORDER BY Id;

SELECT IdempotencyKey, RequestHash, ResultHash, ResultJson
FROM dbo.IdempotencyRecord WHERE WorkflowInstanceId = @instance;

SELECT m.SectionKey, m.PayloadJson, m.SavedByUserId, m.CorrelationId
FROM dbo.MockSectionData m
JOIN dbo.WorkflowInstance i ON i.BusinessObjectType = m.BusinessObjectType
  AND i.BusinessObjectId = m.BusinessObjectId
WHERE i.WorkflowInstanceId = @instance ORDER BY m.Id;

Compare the task and outbox recipient JSON. For the console sample, expect the exact arrays in sample 02. For API execution, inspect NotificationRecipientRule by the route's ID and WorkflowParticipant by instance ID. The two paths can produce different audiences.

Verification commands

Run from the repo root. SQL tests recreate suite-specific databases. Use a local test server and do not run competing test sessions against the same suite databases. TestSqlConnectionFactory.ConnectionString replaces the connection's database name. WorkflowExecutionValidationTests.CreateSeededContext uses burrito_phase4_execution_tests. SampleExpectationTests uses burrito_phase6_sample_expectation_tests.

$env:WORKFLOW_ENGINE_TEST_CONNECTION_STRING = 'Server=DOLLY;Database=workflowengine;Integrated Security=true;TrustServerCertificate=True;Encrypt=False'
dotnet test src/WorkflowEngine.sln --no-restore --filter 'FullyQualifiedName~WorkflowTransitionTests|FullyQualifiedName~WorkflowExecutionValidationTests|FullyQualifiedName~WorkflowSamplesTests|FullyQualifiedName~SampleExpectationTests|FullyQualifiedName~SeedDataSmokeTests|FullyQualifiedName~ReadmeValidationTests' -warnaserror
dotnet test workflow-api/WorkflowEngine.WorkflowApi.slnx --no-restore --filter 'FullyQualifiedName~WorkflowActionServiceTests|FullyQualifiedName~WorkflowActionControllerTests' -warnaserror

--no-restore assumes restored dependencies. On a fresh clone, follow the root README setup first.

Useful debugger tests:

dotnet test src/WorkflowEngine.sln --no-restore --filter 'FullyQualifiedName~SubmitForCheckerWithMissingNotificationTokenReturnsValidationFailedAndRollsBackSideEffects|FullyQualifiedName~SaveDraftVersionConcurrencyConflictDoesNotSaveSectionData'

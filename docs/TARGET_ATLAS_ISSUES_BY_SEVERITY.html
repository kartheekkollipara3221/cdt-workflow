CP Atlas issues by severity

This document lists the issues in the CP Atlas application. It covers the framework, security, the business modules, the UI, the configuration and the workflow engine integration.

Language. This document uses ASD-STE100 Simplified Technical English at approximately 80% compliance. Code names, table names and JSON keys stay as they are in the source.

Ownership. The target team owns the CP Atlas code. Each issue is a finding for that team. No issue in this list needs a change to the workflow engine.

Source. target-implementation-read-only/. Line numbers refer to these .txt copies. Some copies have copy errors. Sections 4 and 5 list the items that are not issues. An item marked Confirm depends on files that are not in the copy (for example the live database or a deployed configuration file).

See TARGET_ATLAS_APPLICATION_FLOW.html for the application flow.

1. High

H1A user can download any file from the server Security

v1/Download joins the id and name parameters to the attachment folder path. It does not check the parameters.

Location
Atlasapp/Atlasapp/Controllers/V1/CPAtlasController.cs.txt:73-90
Example
A user sends id=..\.. and name=appsettings.json. The server returns the configuration file.
Recommendation
Find the attachment by its database ID. Check the user access. Read only from the attachment folder.

H2A file name from the client can write outside the upload folder Security

MapData uses the second part of file.FileName (after #$#) as the file path in the temporary folder.

Location
Service/CPApplicationService.cs.txt:109-121
Example
A file part has the name General#$#..\..\x.aspx. The server writes the file two folders higher. The clean-up does not remove it.
Recommendation
Use Path.GetFileName on the name. Write to a new random file name.

H3A request can set any entity field Security

MapData sets each public property whose name is in Outputs. It does not use the list of controls on the page.

Location
Service/CPApplicationService.cs.txt:83-107; used by all modules (for example CPCDTServices.txt:161, 204)
Example
A user adds {Name:"WorkflowState", Value:"Completed"} or {Name:"IsDeleted", Value:"true"}. The service saves the value. The CDT action conditions also read WorkflowState, so the request can change the selected action.
Recommendation
Map only the fields of the enabled controls on the current step or section.

H4The server does not check access on save, delete and attachment removal Security

The roles, states and owner rules only set the flags in the page response. ManagePage, RemovePage and RemoveAttachment do not check them again. CDT sends the step roles from the config (for example Checker) as the engine actor roles. The engine role check therefore always agrees for CDT.

Location
CPCDTServices.txt:151, 332-354, 704; CPSQMSOService.txt:158; CPTTDService.cs.txt:125; CPAINService.cs.txt:68
Example
A user with only a BDRM role sends a save for the CheckerReview step. The engine gets actor role Checker and approves the trade.
Recommendation
On each write, check the user module roles against the step or rule roles. Send the real user roles (mapped to engine roles) as the actor roles.

H5The dashboard can run script from stored data UISecurity

The ag-grid renderer for AccountInformation builds HTML from params.value. It does not encode the value. The group renderer has the same pattern.

Location
WebUi/.../cp-atlas-dashboard.ts.txt:225-228, 158-160
Example
A user saves an account information value that contains <img src=x onerror=...>. The script runs for each user who opens the CDT dashboard.
Recommendation
Make the link with DOM methods, or encode the value before it goes into the HTML.

H6Engine state and Atlas data can become different Workflow

The service calls Start or Execute inside the Atlas transaction. The engine uses a different DbContext and commits its own transaction. If a later step fails, the Atlas data rolls back, but the engine state and the queued emails stay.

Location
CPCDTServices.txt:156-328; CPSQMSOService.txt:178-237; CPSQMSBService.cs.txt:222-280
Example
The Checker approves. The engine moves to TradingDeskReview and sends the email. The security-identifier save then fails. CDT_General.WorkflowState stays CheckerReview.
Recommendation
Do all Atlas writes first. Call the engine last, immediately before the commit. Alternatively, share one connection and transaction.

H7Save errors are hidden, and some modules report success after a rollback Framework

SavePage catches all exceptions. It does not write a log. CDT returns null. SQMSO, SQMSB, TTD and AIN return the result object with the new ID, but the row does not exist.

Location
CPCDTServices.txt:324-328; CPSQMSOService.txt:232-236; CPSQMSBService.cs.txt:275-279; CPTTDService.cs.txt:118-121; CPAINService.cs.txt:128-131
Example
A database error occurs during a TTD save. The UI shows "Record saved successfully". The timesheet is not saved.
Recommendation
Write the exception to the log. Return an error status to the UI.

H8The service does not check the engine result Workflow

The service reads only NewState. It does not read Success or ResultCode. MarkNotificationDeliveryFailed changes the result, but no code reads it after this change.

Location
CPCDTServices.txt:633-634, 762-773, 797-858; CPSQMSOService.txt:476-556
Example
The engine rejects an action. The form data is saved, the state does not change, and the user sees "saved".
Recommendation
If Success is false, roll back. Return ResultCode and Message to the UI.
